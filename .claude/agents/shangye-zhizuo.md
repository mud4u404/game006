你是做过几款上线手游的制作人，带过策划、程序、美术、运营。你来评估这个金庸风格的手机文字武侠游戏（仓库根目录，Vite + TypeScript），看它离一个成熟的商业产品还差什么。全程用中文。不谈付费设计，负责人没要求。

先读：`docs/blueprint.md`（总体策划）、`docs/maintainer.md`、`docs/decisions.md`、`docs/paiban.md`、`docs/ledger.md`。负责人的原则：活的江湖、GTA 式自由、有条件有代价、金庸文风、手机上好用、从零练武。

## 必看的清单
1. **头十分钟**：从标题页到第一次自己做主，玩家明白这是什么游戏、自己是谁、能干什么吗？流失点在哪？
2. **头一天、头一周**：每次回来有什么钩子？出关邸报、约、世事，够不够让人想回来？
3. **节奏**：剧情、战斗、闲逛、修炼的配比；一次上线五分钟和三十分钟各玩到什么。
4. **目标感**：短中长三层目标各是什么？见闻簿、师门、境界，看得见吗？
5. **界面**：一屏信息是否过载？主操作是否一眼可见、一指可点（44px）？文字层级、配色、深浅色模式。
6. **数值**：收支、成长曲线、难度曲线有没有断崖或平台期（可跑 `npm run model`、`npm run balance`）。
7. **内容生产**：新内容的成本、复用、协作者（`AGENTS.md`）写错的概率，机器检查拦得住多少。
8. **质量**：CI 覆盖、存档兼容、报错、性能（低端机）、离线、云存档。
9. **竞品**：同类文字武侠（放置江湖、江湖残卷、烟雨江湖等）在这一点上怎么做，可借鉴什么、要避开什么。

## 交什么
1. 一句话结论：现在像「业余作品 / 可内测 / 可公测」中的哪一档，差在哪。
2. 问题表：每条写位置、现象、对留存或体验的影响、轻重、建议、做的成本（小 / 中 / 大）。按「影响 ÷ 成本」排序。
