## 二、从这份参考里采纳的做法

1. **设计轮和制作轮分开**：剧情的核心矛盾、地图的结构、人物的诉求先定；完整章节、场景细节、全部对白后补。
2. **定优先级的四个标准**：
   - 阻不阻塞别的工作？
   - 有没有大的不确定性？做不成会不会推翻方向？
   - 是不是核心体验？玩家感不感觉得到？
   - 值不值得现在投入？
3. **做一个地区的顺序**：地区矛盾 → 人物关系 → 地点结构 → 可行动的机会 → 任务与对白 → 场景表现。
4. **自由的压力测试**（并进第 040、091 项的验收）：
   - 玩家拒绝开场的人，还有没有合理的路？
   - 提前找到关键人物，事情能不能正常推进？
   - 先得罪某个势力，再接相关的事，会怎样？
   - 办了一半离开，回来时世界是什么样子？
   - 逃跑、求助、谈判，是不是都有完整的结果？
5. **为多人留好架构**（并进第 012、013 项）：
   - 每份状态写明归谁：个人、队伍，还是公共世界；
   - 战斗、交易、掉落、任务结果都由可信的一方结算，用防重复领取的凭据；
   - 写清单人、组队、离线三种情况下时间怎么走。

   第一版不做联机，但行动协议和状态结构要为它留好口子。

**没有采纳的**：参考里又提了把战斗改成「距离、步法、气力」制。负责人已认可现有的战斗形式，这条记作设计卡备选，不进第一版。

## 三、系统设计卡（新想法都用它进库）

| 要写清 | 要回答 |
|---|---|
| 玩家价值 | 带来什么体验、判断或情感？ |
| 核心规则 | 怎样发生、怎样变化、怎样结束？ |
| 系统联系 | 要用哪些模块，又影响哪些模块？（对照 `docs/fangan.md` 的十二模块） |
| 最小版本 | 用多小的实现就能验证它？ |
| 验收标准 | 怎样证明它有趣、清楚、运行可靠？ |
| 扩展方向 | 验证后还能长出什么？ |

**例：伤情与医疗（第 17 项）**
- 玩家价值：伤改变打法，治伤生出选择、职业和人情。
- 核心规则：分四层。即时状态（气力、失血、运功紊乱）；持续伤情（臂伤、腿伤、内伤、中毒）；恢复过程（包扎、服药、休养、求医）；长期痕迹（伤疤、旧伤、记忆）。
- 系统联系：身体管伤；武学读伤（右臂伤，重兵器招式受影响）；经济管药材与诊金；人物关系记救命之恩；事件把疑难病症变成后续的事。
- 最小版本：外伤、内伤、中毒三类，几种处理办法。
- 验收：伤了的人有路可走（换打法、找人帮、求医、冒险硬撑），养伤的日子里也有值得做的事。
- 扩展：医者职业、采药、医馆经营、特殊病症牵出的故事。

设计卡写好放进 `docs/kapian/`（一张一页）。进开发前，按第二节的四个标准排进 `docs/renwu-100.md` 或下一批。
