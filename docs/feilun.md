# 迭代飞轮：开发进度从哪里来

负责人 10-10 的问题：「任务总有做完的一天，那么你如何帮助我产生新的开发进度？……我希望你有个长期目标，不断派发任务，并且过程中不断感知游戏的变化和需求，从而衍生出新的想法和方向，自主迭代升级。」

只有任务清单不够。要有一个自己会转的机制：长期目标看得见；定期去「看」游戏现在什么样；拿看到的和目标比，差在哪，就从哪长出新想法、新方向，再拆成任务。从 0 到 1 是这样来的（愿景 → 地基和北极星 → 真实试玩 → 骨干计划 → 一百个任务），以后也一直这样转，只是从「偶尔做一次」变成「按节拍做」。

## 五步

| 步 | 做什么 | 谁做 | 节拍 |
|---|---|---|---|
| ① 目标 | 北极星（`docs/gugan.md` 开头）：从一个没钱、没本事、没人认识的人，成长为有能力、有牵挂、能改变一方局面的人。版本阶梯见 `docs/renwu-300.md`：V0.1 一城体验版（扬州）→ V0.2 第一卷完整 → V0.3 镇江……当前站是第一个可玩里程碑（第 020 项，进度见看板） | 负责人定方向，维护者守 | 每个版本对一次 |
| ② 感知 | 看游戏此刻到底怎么样（见下「感知的来源」） | haiku、sonnet 跑；协作者写核对报告 | 每日一轮；里程碑末一次大的 |
| ③ 思考 | 拿感知到的和北极星比，找差距最大的三处；判断是修补、加深，还是开新方向 | 维护者（opus）；Codex 独立再看一遍，两个大脑对照 | 每日一页纸；里程碑末一次大的 |
| ④ 拆解 | 差距写成带出处的任务进备用池；方向上的事给负责人一页纸，点头再拆 | 维护者拆内容和检查，Codex 拆引擎（总单 #293） | 随时 |
| ⑤ 验收 | 做完再量，数字变好了就固化成检查（进 CI），没变好就回到③ | CI、机器玩家、试玩 | 每个 PR；每个里程碑 |

例：真实玩家说「任务没线索」（②）→ 判断是北极星里「知道下一步去哪」断了（③）→ 线索检查 `tests/xiansuo.test.ts` 和一批补线索的任务（④）→ 检查进 CI，新写的事没线索就红（⑤）。下一轮②若测出「线索有了，可做的事太少」，下一个方向就是「江湖自己生事」。

## 感知的来源

1. **机器玩家**：`tests/zoubian.test.ts`（走遍全部内容）、闲逛指标（`docs/huojianghu.md`：有意义的决定多久一个、无事可做几次、想关掉几次）、`tests/xiansuo.test.ts`（线索）、平衡矩阵（`npm run balance`）。
2. **三个审查角色**（`.claude/agents/`，`docs/zishen.md`）：MUD 老玩家、商业制作人、金庸编辑，轮流试玩最新版本。
3. **真实玩家**：负责人转来的反馈，原话记进 `docs/ledger.md` 的台账。
4. **协作者的核对报告**：如 `docs/hexue-rumen.md`、`docs/xiansuo-duanxian.md`。
5. **看板**（`/kanban/`）：合并节奏、谁闲着、哪里卡住。
6. **同类作品**（负责人 10-10：「有些东西你可以参考北大侠客行的……没事干就去研究下」）：公开的武侠 MUD 源码（侠客行系等）怎么做门派地图、练功、门派生活，笔记在知识库 `docs/zhishiku/`；只借机制和布局，不抄文字和代码。每日巡视没有急活时研究一块；调研排成任务，交给协作者。
7. **灵感本**（`docs/linggan.md`）：谁有想法都记一笔，每日巡视挑三条；每周一次灵感会（三个审查角色加 Codex 各提「如果……会怎样」）；从金庸原著的名场面倒推玩法。

## 什么时候开新方向

满足任一条就开，不等清单做完：
- 同一类毛病，在两个以上来源里出现（例：机器查出断线，真实玩家也说没线索）；
- 某个北极星指标连着两轮没变好；
- 当前这一片的计划完成过半，下一片的前置已经具备。

方向级的事（大系统、改主线设定）照 `CLAUDE.md` 第二节，写一页纸、给推荐项，等负责人点头。其余的维护者自己定，写进 `docs/decisions.md`。

## 节拍

- **每小时巡检**：每家有活、合并不卡、关键路径不停（`CLAUDE.md` 第三之二节）。
- **每日巡视**：先感知（机器数字，加一个审查角色试玩），再对照北极星思考，发现的进台账、拆成任务。最后给负责人一页纸：昨天合了什么、新发现、今天想做的三件、要负责人定的事。
- **里程碑复盘**：里程碑的件数清零时，四个角色完整试玩一遍，Codex 独立评估，维护者写出下一个里程碑的计划，交负责人。这就是从一版跳到下一版的那一步。
