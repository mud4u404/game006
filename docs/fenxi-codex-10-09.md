### 统计方法

统计的是运行时合并后的注册表，不按文件名猜包数或按文档抄规模。`src/content/index.ts:13` 自动载入全部包，`:34` 合并定义，`:59` 合并人物挂接、地点活气和人物活气。以下为本次统计方法，可在仓库根目录以安装好的 Vite 执行；递归扫描既计入对话，也计入剧情、对手结算和世事步骤，计数是定义数量，不代表条件全部可满足。

```js
// 用 node --input-type=module 执行，依赖当前仓库的 vite。
import fs from 'node:fs';
import { createServer } from 'vite';
const server = await createServer({ server: { middlewareMode: true }, logLevel: 'error' });
try {
  const c = await server.ssrLoadModule('/src/content/index.ts');
  const keys = ['ROOMS', 'NPCS', 'FOES', 'QUESTS', 'STORIES', 'ITEMS',
    'NEWS', 'SKILLS', 'ENCOUNTERS', 'JOBS', 'EYES', 'SHI', 'FACTIONS'];
  const data = Object.fromEntries(keys.map(k => [k, c[k]]));
  const all = []; const walk = x => {
    if (!x || typeof x !== 'object') return;
    if (x.type) all.push(x);
    Object.values(x).forEach(walk);
  }; walk(data);
  const learned = new Set(all.filter(e => e.type === 'learn').map(e => e.skill));
  ['hanjiang', 'xinfa', 'taxue'].forEach(id => learned.add(id));
  console.log('包', fs.readdirSync('src/content/packs').filter(f => f.endsWith('.ts')).length);
  console.log(Object.fromEntries(keys.map(k => [k, c[k].length])));
  console.log('人物', c.NPCS.filter(n => !n.obj).length, '物件', c.NPCS.filter(n => n.obj).length);
  console.log('有授予或起始接线的武功', learned.size);
  console.log('可拜门派', [...new Set(all.filter(e => e.type === 'sect').map(e => e.school))]);
  console.log('地位授予', all.filter(e => e.type === 'sect').map(e => e.rank));
  console.log('世界写入', all.filter(e => e.type === 'w'));
} finally { await server.close(); }
```

扩展统计：地区按 `ROOMS.region` 分组，人物取合并后该地区 `npcs` 中非 `obj` 的不同 id，物件取 `objs` 的不同 id；不考虑作息及剧情条件，因此不是同一时刻站着的人数。武功以 id 去重；拜师按 `sect` 效果的不同 `school` 去重；重复世事按 `again`，一次路遇按 `once`；被动及合璧分别按 `SKILLS.passive`、`SKILLS.combos` 非空统计。`w` 写入按递归效果计数，`w` 读取按含 `if.w` 的条件对象计数。下文引用“注册表统计”均指此口径。

### 问题（按玩家伤害排序）

1. **H1：长久闲逛的变化来源不足。** 13/14 世事没有重来设置，27/32 路遇是一次性；已知材料消耗完之后，不会自动变成新的关系冲突。`dayPass` 主要令数值回归基线、消除临时伤势；在当前包中没找到按势力所求选择新模板的内容接线。“到处乱逛，没有任何的收获”会在长期再次出现。建议先用现有人与地点接一条可以反复变化的小事，不先扩几十个静态包。证据：注册表统计；`src/engine/shijie.ts:145`；`src/engine/encounter.ts:24`；P6、P10（`docs/charter.md:21`、`:25`）。没有长期真人留存数据，枯竭发生在第几日标 **存疑**。
2. **H2：文字后果有时超过世界实际后果。** 码头调停写“白天归东舵，夜里归西舵”，实际只 `owner: dong`，标记只是“旗子一日换两回”的文字，没有昼夜切换主人。既然船费真的按主人算，玩家选择共享与夺回东舵会得到不同叙述、相同主人收费机制。建议实现对应时段的治理规则，或改成实际存在的共管分账，保证下一次登船可感知差异。证据：`src/content/packs/shishi-yangzhou.ts:65`、`:67`；`src/content/packs/yz-shili.ts:35`；`src/engine/shijie.ts:145`。对照 P9（`:24`）。未在浏览器打出此结局，结论为代码级确定，不是实玩结论。
3. **H3：“所有帮派都有自己的地盘”只局部兑现。** 6 个世界势力全属扬州，初始只有东舵、府衙、盐号、丐帮 4 个有 `holds`；西舵与黑风寨没有初始据点。镇江和苏州的帮会虽有地点、台词，尚未进入同一势力治理模型。建议区别山门可进、势力据点、地方谁管三种事实，不用一个统一数冒充全部覆盖。证据：`src/content/packs/yz-shili.ts:13`、`:16`、`:26`；地区统计；负责人原话。不能据此称九派都“没有地盘”，有实体山门的情况见第三节。
