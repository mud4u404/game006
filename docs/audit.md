# 健康度审查（清道夫）

负责人的建议：

> 伴随着开发进展，很多功能或选项可能会失去意义，需要有个清道夫和审核官，对游戏每一处进行判断：这是什么，这有没有意义，没有它会怎样，如果优化会不会更好。我想这样游戏会保持很高的健康度。

本文件就是这位清道夫的账本。游戏里每一个系统、每一个界面元素、每一项数值，都要在这里回答**四问**：

1. **这是什么**：它在游戏里的样子。
2. **有没有意义**：玩家看到它、用到它时，得到了什么。
3. **没有它会怎样**：删掉以后，游戏少了什么，还是什么都没少。
4. **改了会不会更好**：有没有更简单、更有趣、更省事的做法。

结论只有四种：**留**、**改**、**删**、**并**（并进别的系统）。

## 一、怎么审

**机器审（CI，每次提交都跑）**。凡是能写成规则的，都交给机器：
- 任务走得完：每一阶段都有内容能推进到下一阶段（`tests/content.test.ts`）；
- 每个可点的动作都有回应，最后一个分支不带条件；
- 地点往返相通，同一区域互相走得到；没放到任何地点的人物会被指出；
- 门派打法不雷同、谁也不能独大（`tests/menpai.test.ts`、`tests/balance.test.ts`）；
- 已发出去的 id 只增不删，存档不坏（`tests/ids.test.ts`、`tests/save.test.ts`）。

**人审（每日一审，见 `docs/auto-review.md` 第〇节之后的「清道夫」一步）**：
- 每天从下面的清单里，按「上次审查」最早的顺序挑至少五项重审，四问逐条回答，更新结论和日期。
- 结论是「改」「删」「并」的，当天开任务，或者在维护者自己的 PR 里做掉。
- 发现能写成规则的，补一条机器检查。机器审不了的，才留给人审。
- 新功能上线时，PR 正文必须回答四问；不回答的不合并。

## 三、根基五项怎么改（已做，见 `src/engine/gengu.ts`）

每一项都要有看得见的作用，并且能长：

| 根基 | 作用 |
|---|---|
| 体魄 | 气血上限；受伤后恢复快慢；斗酒、负重一类的体力检定 |
| 根骨 | 内力上限、每合回内；内功练得快；硬接 |
| 身法 | 闪避、先手；赶路省时间；轻功练得快 |
| 悟性 | 外功练得快；上乘武功的门槛（`needAttr`）；观察时看出线索、解谜 |
| 胆魄 | 抢攻；怒气涨得快；对话里的威吓、斗酒；面对强敌不失势 |

- **成长**：奇遇、丹药、武功突破都能长根基。例如内功每突破到炉火纯青，根骨加一。根基有上限，前期每一点都珍贵。
- **人物页**：每项根基旁边写明它现在带来了什么，例如「气血上限 1120」，不写空话。

## 四、人情怎么改（已做，见 `src/engine/renqing.ts`、人物页）

- **只列有意义的人**：关系离开了「素不相识」「点头之交」的；有任务在身的；有恩怨的；师门的。
- **其余收起来**：一行「萍水相逢 N 人」，点开才看。
- **分组**：师友、恩怨、托付（有事相求或你有事求他）。
- **每个人写清**：是谁（身份）、在哪（常在的地点）、为什么记得他（最近一件事）。
- **关系称谓**只用关系阶梯里的词，机器检查。
