# 011 现有代码对照与最小构建

对应 `docs/renwu-100.md` 第 011 项。依据：`docs/fangan.md`（四层、十二模块、行动协议、九条规则）、`docs/sheji-012-013.md`、`docs/sheji-021-026.md`。核对的代码是 `origin/main` 的 `d5ed2b3`（10-10）。

负责人 10-10 的批评：「嘴上说按一百个任务重做，实际还在老版本上修修补补。」本文先回答这句话对不对，再给逐模块对照。

## 一、先说结论

1. **批评基本成立，但要分两段看。** 10-08 到 10-09 的「大换血」和「活的江湖」是真重写：人和交手（`person.ts`、`duel.ts`）、世界状态（`shijie.ts`）、传闻（`chuanwen.ts`）、时间与身份（`shiguang.ts`、`shenfen.ts`）。这批底子是好的，应该留。**但一百个任务方案定稿（10-09 夜）之后，架构层的核心三件事一件也没动**：`engine/xingdong.ts` 不存在，没有 `plan/act`，存档没有 `log`，没有防重复的 `key`。方案之后的 33 个非合并提交里，`src/core`、`engine`、`ui`、`net` 共改了 +978/−193 行，其中新文件只有 4 个共 286 行（`beidong.ts` 71、`cengji.ts` 36、`chufa.ts` 79、`kaipian.ts` 100），其余约 690 行都加在旧文件的旧分支里。同期内容包 +2,541 行、测试 +2,642 行、文档 +1,860 行。
2. **该推倒的比想象的少，约 900 行**（占 `core + engine + ui + net` 共 9,856 行的一成）：`dsl.ts` 的 `run()` 结算内核约 200 行；`ui/explore.ts` 的赶路、歇脚、闭关、搭配动作约 130 行；旧战斗内核 `combat.ts + build.ts + sim.ts` 532 行（退役删除，不是重写）；散在四处各写一遍的「此刻谁在哪」约 60 行；`kaipian.ts` 把断点塞进旗标的约 40 行。其余八千多行结构是对的，是**补**，不是重写。
3. **先动结算内核。** 九条规则里最伤的几条（钱扣到零照样给、反复领、没有事件记录、结果与预告各算各的）都出在 `run()` 这一个口子上，人物自主行动、事件记录、复现、界面反馈都要接它。建议次序见第五节：先加一道「不准再新增直调」的棘轮测试止血（半天），再建 `xingdong.ts`，然后按「交差、买卖与赶路、学艺」三类逐个把旧调用收进去，每一步独立合并、游戏一直能玩、旧档照读。

## 二、总表

「结论」三选一：**保留**＝已合新架构，只清理和加检查；**改造**＝结构对，要补缺或搬动职责；**重写**＝结构就不对，补丁会越打越多。「重写」都是**原位分步**（先包一层、再换里面、旧的当场删），不开分支，不动内容格式（`Cond`/`Effect`）、存档字段和测试，与 `decisions.md`「不推倒，换中心改造」一致。工作量是**构架层**的人日（不含新增内容、不含界面新功能），粗估，误差一半。

## 四、逐模块展开

### 1 状态与结算　结论：重写（结算内核）

**职责**：条件、成本、效果、事务；状态只能从结算口改（`fangan.md`）。

**现在落在哪**
- `core/state.ts`（226 行）：`GameState` 56 个字段（`:21`），全局单例 `S`（`:203`），`newGame`、`skipToYangzhou`。
- `engine/dsl.ts`（397 行）：`test()`（`:43-110`，条件约 60 个字段）、`run()`（`:186-388`，42 个 case）、`lackOf`、`dismiss`。
- 效果的实际执行还散在 `jiesuan.ts`（192）、`daoju.ts`（123）、`growth.ts`（80）、`shenfen.ts`（74）。
- `run()` 的调用点 13 处：`fight.ts:957,1008`、`explore.ts:218`、`story.ts:81`、`world.ts:265,269,278,323`、`daoju.ts:73,85`、`shishi.ts:52`、`jiesuan.ts:77`、`shiguang.ts:199`。

**差距**
- 规则三：没有 `key`、没有事件记录。反复领钱的防法是四种不同的补丁（见 3.1）。
- 钱扣到零照给：`dsl.ts:204-208` 是 `Math.max(0, S.silver + e.delta)`。所以才要 `tests/qian.test.ts` 逼每个内容分支手写 `silver` 条件（只覆盖剧情选项和人物动作，战斗结算、差事、道具 `use` 不在其内）。
- 无 `plan`：按钮标价、标赏、出发提示三处各自反解分支（`world.ts:192/214`、`chufa.ts:60`），只认 `silver` 和 `job` 两类。
- 无事务：`run()` 一个个就地改 `S`，中途失败不回滚（如 `learn` 学不成只发一条提示就继续，`dsl.ts:232`）。
- 界面提示夹在结算里：`pushFeed`、`emit('toast')` 散在十几个 case 里（`dsl.ts:201-203`、`360-361`…）；`fight.ts:916` 的 `rewardChips` 按「效果清单」自己拼奖励，不是按实际变动。
- 规则散在分支里且各写一遍：「做回游侠」`S.shenfen = { id: 'youxia', … }` 在 `dsl.ts:182`、`254` 各写了一遍，`jobFail` 里又单独判一遍（`:378-382`）。
- 无连锁上限：`'shi'` 效果 → `moveShi` → `goStep` → `run(step.do)`（`dsl.ts:200`、`shishi.ts:52,111`）；`jobFail` → `run([standing])` → `dismiss`（`dsl.ts:382`、`326`）。都没有深度限制。
- 钱有 5 个写入口：`dsl.ts:204,364`、`world.ts:86`、`daoju.ts:121`、`shiguang.ts:157`，都不记账。
- 人物进不来：`engine` 里 12 个文件引用全局 `S`，纯的只有 `duel/person/beidong/cengji/combat/build/sim/rng`。没有 `who`。
- 增长趋势：10-10 又往里加了 `today` 一种效果、`silver.if`、`silver.note`。规格写完以后，旧入口还在长。

**为什么重写不是改造**：`plan/act` 的外壳能包住旧 `run()`，但包不出「要么全成、要么全不成」，因为 42 个 case 就地改全局、夹带界面提示、互相递归。补丁式做法会得到「外壳 + 旧 run」双轨，旧的永远删不掉。做法：`Cond`/`Effect` 数据格式和 `test()` 原样保留（内容 17,900 行不动）；新 `xingdong.act` 先按类型把效果分成代价和结果、先算后用；`dismiss`、`leaveSect`、`jobFail` 这些规则挪回 `shenfen.ts`、`shicheng.ts`；`run()` 退成 `act` 的内部一步（规格本就这样写），最后界面和内容不再直调（测试检查）。

**工作量 12 人日**：`xingdong.ts`（`plan/act`、`EventRec`、`key`、连锁上限、`log` 字段）5；三类迁移（交差 1.5、买卖 1.5、学艺 1）4；其余 13 个调用点收口、钱的写入口收口、「禁止直调」检查 3。

### 2 时间与调度　结论：改造

**职责**：江湖时间、行动耗时、战斗节拍、离线；各模块不私改日历。

**现在落在哪**：`core/time.ts`（76 行：`dayNo`、`absMin`、`advanceMin/advanceDays`、`spanLabel`、`setNowMs`）；`engine/shiguang.ts`（255 行：`allowance`、`restDays`、`jingxiu`、`settleAway`、`checkYue`）；`shishi.ts:70` 的 `tickShiFull`；`shijie.ts:145-183` 的 `dayPass/tickWorld`；`ui/shell.ts:186` 的 `render()`。

## 五、建议的重构次序

原则：**每一步独立合并；合并后游戏照样能玩；旧档照读**。具体做法：每步先包后换（新入口先包住旧行为，测试照旧全绿，再把调用点一类一类迁过去，最后删旧的）；存档只增可缺省字段（照 `dayLog` 先例，`repair` 补默认，不升版本）；每一步的验收是机器检查，不靠人看。机器玩家 `tests/zoubian.test.ts`、旧档夹具 `tests/save.test.ts`、`npm run check` 是每一步的共同底线。
