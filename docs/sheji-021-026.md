# 第 021～026 项规格：人物的诉求、持有、作息、恩怨、所知、自己行动

对应 `docs/renwu-100.md` 第 021～026 项（人物与关系的骨架）。依据 `docs/sheji-004-007.md` 第 005 项（二十个关键人）、`docs/sheji-012-013.md`（状态归属、行动协议）、`docs/fangan.md` 规则四（人只按所知行动）。

**原则**：在现有的上面长，不另起一套。存档字段只增不删。

## 现状（10-09 核对）

已经有的，照用：
- **作息**：`NpcDef.at` 写几处，各带时辰条件；事件打断作息记在 `PersonState.at`（`src/engine/shijie.ts`），`whereNow` 定此刻在哪。
- **处境**：`PersonState.st`（伤、坐牢、走了、死了）和 `until`。
- **所知**：`PersonState.know` 记他知道的传闻，同处一地的人互相说，嘴碎的说得多（`src/engine/chuanwen.ts`）；打听就是问他知道什么。
- **声口与行当**：`NpcLife`（`trade`、`faction`、`talk`、`voice`），扬州一带约五十人已写（`yz-ren*.ts`、`gz-ren.ts` 等，用 `ContentPack.npcLife` 补）。
- **关系**：阶梯词（`src/engine/renqing.ts`）、人情备注 `relNote`。

缺的：人**想要什么**、**不肯做什么**、**手里有什么**；关系变化**没有原因**；人**自己不动**。

## 021 诉求与底线

写在 `NpcLife` 上（新字段，可选；二十个关键人必写）：

```ts
interface NpcLife {
  // ……现有字段
  /** 想要的：按处境挑第一条成立的（和分支一样，最后一条不带条件） */
  want?: { k: string; text: string; if?: Cond }[];
  /** 怕的：一句话，打听、细看时用 */
  fear?: string;
  /** 底线：什么情况下他不肯做某件事，原因原样给玩家看 */
  refuse?: { verb: Verb | '*'; if?: Cond; why: string }[];
}
```

- `want` 的条件读世界和玩家的状态，**处境一变，想要的就变**。例：码头被西舵夺了以后，东舵舵主想要的从「守住船脚钱」变成「夺回码头」。
- `refuse` 接进行动协议：`plan()` 先查 `refuseOf(人, 动作)`，成立就 `ok:false`、`why` 用这句。界面照 013 的做法灰掉按钮、写原因。
- **玩家怎么知道**：
  - 关系到「相谈甚欢」，细看时多一行「他眼下想……」；
  - 打听这人时，熟悉他的人（同一股势力、同一处）可能说出来；
  - 不挂标签，不报数（规则五）。
- 验收：二十人各有至少两条随处境变的诉求、一条底线；单元测试改了处境，`wantOf` 换了一条；被 `refuse` 拦下的动作什么也不扣。

## 022 持有

存在世界里（个人的东西放 `PersonState`，归世界模块，见 012）：

```ts
interface PersonState {
  // ……现有字段
  /** 手里有什么：银子（文）和物品 id → 数量。只存和开局不同的 */
  has?: Record<string, number>;
}
// 开局的：NpcLife.has?: Record<string, number>
```

- 内容里「他给你东西、给你钱」的效果，走行动协议时从 `has` 里扣；**没有就交不出**，`why` 写「他手里没有」。开店的不在此列（店照现有的进货规则，第 033 项再接库存）。
- 人怎么得到东西：开局给的、玩家给的（赠礼、付钱）、自己行动得来的（024）。全记事件。
- 验收：一个人把仅有的一样东西给了你，再找他要，交不出；给他钱以后，他能拿去做事（024 的采购）。

## 023 作息与公开去处

作息照旧用 `NpcDef.at`。补两件：
1. **同一时刻只在一处**：CI 检查每个人一天里每个时辰，`at` 的条件最多一条成立（规则：作息不重叠）。
2. **打听去处**：问某人「某某平日在哪」，答的是**作息的公开部分**（`at` 里不标 `secret` 的），只有认识他的人（同一股势力、同一处、关系在点头之交以上）答得出；答出来的记进见闻簿。事件打断作息时，知道这件事的人才说得出新去处。
- 验收：在一个人常去的地方等不到他（他被事件叫走了），去问认识他的人，能问到他去了哪；问不认识他的人，只说不知道。

## 024 人物自己行动

每日推进（`dayPass`）时，**有诉求的人**（写了 `want` 的）各自挑一件事做，走同一个 `act()`，`who` 填他的 id：

| 动作 | 什么时候做 | 结果 |
|---|---|---|
| 求助 | 诉求办不成、手里不够 | 生一件求玩家或别人帮忙的事（第 027 项） |
| 采购 | 手里有钱、缺某样 | 从当地铺子买，扣他的钱，进他的持有 |
| 赴约 | 事件给他定了约 | `PersonState.at` 放到约的地方 |
| 躲避 | 他怕的事临头（地方有了相应的痕迹、仇人到了） | 离开几日（`st:'gone'`）或换处待着 |

- **上限**：一片地方一日最多三个人自己行动；同一人隔三日以上才再动（第 038 项的冷却同理）。
- 随机只用世界种子（`worldRng`），同一个种子一字不差（规则九）。
- 人做的事和玩家做的一样记事件，**知道的人照传闻的规矩传开**（谁在场谁知道）。
- 第一版只做这四个动作；动作表放在 `src/engine/renxing.ts`（新文件），内容只写诉求和持有，不写每日剧本。
- 验收：连着推十日，日志里每个人做的事都能用他的诉求和处境解释；没有人在同一日做两件事。

## 025 人情与恩怨的原因

- 关系阶梯照旧。改的是：**每一次关系变化都由一条事件引起**，`rel` 效果走协议时把事件流水号记在 `relNote` 旁边（`relWhy?: Record<人, number[]>`，最近三条）。
- 另加一个看不见的账 `PersonState.you`（恩为正、怨为负，负一百到一百），和势力的 `FacState.you` 一样：小恩小怨攒着，到了线才动阶梯。阶梯是玩家看得见的，账不报数。
- 账影响什么：
  - 求助先找谁：账高的先找你；
  - 底线松不松：账够高，有的 `refuse` 不成立，内容里用条件写；
  - 恩怨记仇：账低于负五十，他在合适的时候会自己找上门（024 的动作，第 039 项接）。
- 人物页一个人底下，列「他记得你做过的事」，读事件记录（第 048 项），不读旗标。
- 验收：一件事让某人的关系降了一档，人物页能看到是哪件事；同样的事做两遍，账只记一次（凭 `key`）。

## 026 所知与来处

所知分两种：
1. **听来的**：传闻，已经有（`know`）。
2. **本来知道的**：`NpcLife.knows?: { k: string; text: string; if?: Cond; secret?: true }[]`。例：卞婆婆知道二十年前那条船是谁的；书办知道哪张榜还没人揭。`secret` 的，关系到相谈甚欢以上才说。

规矩（规则四，进 CI）：
- 人在对白里说到一件世事、一个人的去处、一桩秘密，**必须出自他的 `know` 或 `knows`**。机器查法：对白里引用世事的写法统一用 `{ask:k}` 一类的标记（实现时定），CI 查标记能对上；写死在文字里的，由三个审查角色抽查。
- 传话保留来处：转述时说一句听谁说的（已有）；**走样不改写事实**：存档里的事实只有一份，走样只在说的时候。
- 验收：一件只有甲在场的事，乙在甲没开口前不知道；甲说给乙以后，乙说的时候带一句「听甲说」。
