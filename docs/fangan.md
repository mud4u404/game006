# 开发方案：先搭骨架，再长血肉（前一百个任务）

负责人 10-09 晚：「我不在乎从头再来，但我非常重视逻辑架构、核心玩法、功能模块；先搭建骨干，再丰富血肉；你可以从一个想法，细化成一个开发方案吗，比如头一百个开发任务是什么。」并转来 Codex 的一稿（四层架构、统一行动协议、不可破坏的规则、最小验证世界）。

本方案合并了维护者和 Codex 两稿：**架构和验收标准以 Codex 稿为主，推进方式以维护者稿为主**（先竖着打通一条最小的完整路线，再一层层加厚；在现有代码上重构，不另起炉灶，见 `docs/decisions.md`「不推倒，换中心改造」）。

## 一、核心玩法

**一句话**：从一个没钱、没本事、没人认识的人，成长为有能力、有牵挂、能改变一方局面的人（北极星，见 `docs/gugan.md`）。

**核心循环**：发现机会 → 判断局势 → 选择行动 → 承担代价 → 得到结果 → 能力与关系改变 → 新的机会。

**三条路线**，各自成立，又共用人物、时间、资源和世界后果：

| 路线 | 玩家做什么 | 乐趣从哪来 |
|---|---|---|
| 江湖生活 | 谋生、结交、介入纷争、选择归属 | 人和局势变了，生出新的选择 |
| 武学成长 | 学艺、实战、修炼、搭配、挑战 | 能力改变解决问题的方式 |
| 探索求知 | 观察、打听、求证、推理、发现秘密 | 新知道的事打开新的路 |

三种乐趣：自主性、能力感、影响力。检验标准：玩家合上手机时，知道今天办成了什么，也惦记着江湖里的某个人、某件事。

## 二、逻辑架构

```
表现层   界面：场景、地图、战斗、人物、见闻簿 —— 只显示玩家有权知道的，只发出「我要做什么」
行动层   行动协议：谁、对谁、做什么、用什么 —— 玩家和人物走同一个协议
规则层   时间、通行、战斗、成长、经济、关系、组织、事件、知识 —— 判断能不能做、花什么、发生什么
事实层   人物、地点、资源、关系、知识、世界状态、事件记录 —— 真正发生过的结果（存档）
内容定义 人物设定、武功、事件模板、对白 —— 只给规则层提供数据和文字，不自己改事实
```

**行动协议**（所有动作都走它：交谈、交易、拜师、交差、偷窃、治伤、走镖、战斗；人物自己行动也走它）：

> 提出行动 → 检查条件 → 定下成本与结果 → 一次结算（要么全成，要么全不成）→ 记一条事件 → 通知相关系统 → 给玩家看实际结果

要事先定死的五件事：耗时的行动开始和完成各查什么；条件不成时哪些扣、哪些退；重复点击和读档不能重复领；一件事引出下一件事时的连锁上限；人物自己行动也要有资源和时间。

**十二个模块**（现状：留＝已有、按边界整理；改＝要改造；新＝要新建）：

| 模块 | 负责 | 边界 | 现状 |
|---|---|---|---|
| 状态与结算 | 条件、成本、效果、事务 | 状态只能从结算口改 | 改（`engine/dsl.ts` 的 `run` 收成结算口） |
| 时间与调度 | 江湖时间、行动耗时、战斗节拍、离线 | 各模块不私改日历 | 留（`core/time.ts`、`engine/shiguang.ts`） |
| 地图与通行 | 地点、路线、交通、费用、风险 | 导航和实际行程同一套路线 | 留（`engine/world.ts`、`daohang.ts`） |
| 人物与关系 | 诉求、资源、作息、所知、人情恩怨 | 人只按自己的处境和所知行动 | 改（缺诉求、记忆、自主行动） |
| 武学与战斗 | 武功、招式、状态、搭配、伤、胜负 | 实战与模拟同一规则；写的效果都要生效 | 留（`duel.ts`、`person.ts`；旧 `combat.ts` 退役） |
| 成长与训练 | 历练、熟练、修炼、突破、评价 | 显示的长进直接来自结算 | 改（缺战力评价） |
| 经济与生活 | 钱货、交易、赏格、债、住处、营生 | 每文钱有来处去处；许诺与实付同一依据 | 改（缺营生阶梯、数值总表） |
| 组织与身份 | 势力、门派、职责、地位、权限、门规 | 身份真实影响能做的事 | 改（内门以上没有） |
| 事件与事务 | 事件触发、发展、差事、约、后果 | 事件只在世界条件成立时发生 | 改（`shishi.ts` 留作「本」，新增诉求驱动的事件） |
| 知识与探索 | 所见所闻、线索、求证、秘密入口 | 玩家知道的和世界真相分开存 | 改（`chuanwen.ts` 留，线头、谜链新建） |
| 存档与复现 | 快照、迁移、事件记录、复现 | 能恢复，也能解释重要变化 | 改（缺事件记录） |
| 界面与反馈 | 手机操作、导航、反馈、回归 | 只显示玩家有权知道的 | 改（突破、分层战报、渐进露出） |

**不可破坏的规则**（写成机器检查，进 CI；新内容都要过）：
1. 同一个人同一时刻只在一处。
2. 交易、许诺的赏格和实付金额用同一份依据。
3. 物品和钱不能凭空复制（同一件事不能领两次）。
4. 人物只按自己知道的事行动和说话。
5. 玩家只看到已经得知或合理看得见的东西。
6. 武功说明里的效果，确实进入实战。
7. 重要选择留下查得到、感觉得到的后果。
8. 读档恢复、离线结算不重复发收益。
9. 同样的起始状态、行动记录和随机种子，结果一字不差。

## 三、怎样证明骨架搭好了

**最小验证世界（沙盘）**：三个地点、四个人、两股势力、三门武功、一件冲突。做成一套测试（真引擎、真规则），也能在试玩页里玩。它要证明：
- 人会自己行动，生出玩家能介入的机会；
- 同一件事，玩家用打、用买卖、用打听来的消息，都解得开；
- 选择改变资源、关系和地方的状态；
- 得来的本事帮得上下一件事；
- 离开再回来，人和世界的变化前后对得上；
- **再加一件同类的事，主要靠配置和内容完成，已有系统接得住它的条件、代价、结果和后果。**

沙盘过了，再把扬州搬上骨架，然后才扩人物、武功和故事。
