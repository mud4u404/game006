# 流水线：几个工具怎样一起干活不撞车、不闲着

负责人 10-09 晚：「请你设计好工作流，分配好工作，确保他们有事情可干，及时发现问题，提高效率。」

## 一、谁做什么

| 工具 | 额度、模型（10-09 晚） | 适合的活 | 不派的活 |
|---|---|---|---|
| Codex（ChatGPT） | 额度多，强 | 要设计、要读很多文件的重活：门派据点、全量审查、大批修订 | 零碎小活（浪费） |

| 维护者（Claude） | — | 引擎、存档、界面、合并、审稿、出任务 | 成批的内容 |

## 二、任务从哪来，怎么不撞车

1. **任务都是 Issue**，打「给:工具名」标签；只有自报名字的那个工具领得到（`node scripts/wait-for-work.mjs --for 名字`）。
2. **同一批任务分到不同的文件**：人物活气的任务，每个只许新建一个文件、点名十个人的 id，谁也不碰谁。
3. **找活**：`npm run kongque` 列出各地区还有哪些人没写活气、哪些地点最冷清。维护者按它开新任务，空闲的协作者也可以照它自己挑，但必须先在 Issue 里留一句「我领 X」，免得两家做同一批。
4. **返工退回原作者**（CLAUDE.md 第四节），维护者只在额度或工具坏了、要等一小时以上，或改动小几分钟能改完时接手。

## 三、任务不断档

每个工具手里至少有「一件在做、一件排着」。维护者每天看两次（早、晚）：

- 谁手上只剩一件，就再开一件，写进「给:他」；
- 谁领了任务两小时没有分支、没有 PR，就在 Issue 里问一句，仍无回音，换人；
- `npm run kongque` 的空缺不够派时，由 Codex 的全量审查（#184）和每日一审（Issue #16）产出新任务。

## 四、及时发现问题

| 机器查 | 人（维护者）查 |
|---|---|
| CI：类型、全部测试、冒烟、机器玩家走遍；`tests/yizhi.test.ts` 的棘轮（撞名、写死兵器、抄来的台词）；场景不挤 | PR 一到，先看「检查真跑了没有」「改了哪些文件」，再抽读文字 |
| 每个 PR 自动合并只看改了哪些文件（只含内容包才合） | 合并后在预览上走一遍；每天给负责人一份「昨天合了什么」 |
| 协作者自己的返工：失败两次就停、说明原因（AGENTS.md 第十节的安全阀） | 毛病多的类型，收紧任务清单（把「先避开的毛病」加长） |

出现新毛病的类型，做两件事：加一条机器检查（写进 `tests/yizhi.test.ts` 的棘轮），再把它写进任务清单。

## 五、一个工具的一天

```
读 AGENTS.md，进入自动模式，你的名字是 <名字>。
```

它会自己：等任务 → 做 → 自检 → 推送 → 看 CI → 回到等任务。负责人不用转述。额度紧的工具，改成「只做 #N，做完停」。
