# 流水线：接力共创，不闲着、不浪费

负责人 10-09 晚：「工作流请你固化，找出接力共创的最佳方案，并且想方设法节省不必要的 token 浪费，不要让 AI 们赋闲」「Opus、Sonnet、Haiku 三个模型对应不同难度的任务」「不为了让工具有事干而造任务」（CLAUDE.md 第三节之二）。

一句话：**维护者把大事拆成一池写清了的真任务，用「依赖」串好，小弟和助手自己从池子里接着领；机器验收，维护者只看结论。**

## 一、四档人手

| 档 | 做什么 | 不做什么 |
|---|---|---|
| **Opus**（维护者主线程） | 定方向、拆任务、写规格和验收、写样板（金庸文字的最后把关）、审结论、合并、给负责人汇报 | 不亲手写成批代码和内容，不亲手跑测试、查日志、统计 |
| **Sonnet**（子助手） | 照规格写引擎和界面、修 bug、复审黄档 PR、试玩 | 不定方向 |
| **Haiku**（子助手） | 跑测试并汇总、查 CI 日志、对比、统计、按清单的机械操作（合并主线、改标签） | 不改设计、不写新文字 |

返工默认退回原作者；维护者只在作者的额度或工具坏了、要等一小时以上，或改动很小几分钟能改完时才接手（详见 `docs/auto-review.md`）。
| **小弟**（外部工具，不花我们的 token） | 规格写得清、机器验得了的活，见第二节 | 要判断方向的、跨很多文件写不清规格的 |

**同一件活能下放就下放**：小弟能做的不给 sonnet，sonnet 能做的不给 opus。

## 三、任务池：怎么做到不闲着又不造任务

1. **任务只从骨干计划拆出来**（`docs/gugan.md`、`docs/renwu-pi1.md`），每件 Issue 第一段写「为什么要做」。写不出来就不开。
2. **先抓大，再抓小**：一段工作先定顺序和样板，再拆成能并行的小件，**一次拆够一批**（至少够每个在线的工具各一件在做、一件排着）。
3. **用「依赖：#N」串成链**：后一件写在前一件后面，前一件合并，`wait-for-work.mjs` 自动放行后一件。工具做完一件马上领下一件，不等维护者传话。
4. **能并行的拆成按文件不重叠的小片**：例如武学描写分层，按门派切开，minimax、Qoder、Trae 各领几门，同时写，谁也不碰谁的文件。
5. **池子见底时**：先看有没有被样板、规格卡住的（维护者优先写样板和规格，这是瓶颈）；真没有，如实告诉负责人「某某现在没有任务」，不拿缺口表凑数。
6. **冻结的东西不派**：不在当前这一段里的（新城、新门派、没入口的武功）打「暂缓」。

## 四、一件任务的一生

```
维护者写 Issue（为什么、做什么、不做什么、验收、允许改的文件、依赖）
  → 小弟：wait-for-work 领到 → 做 → 本地 check → 推分支
  → CI 建 PR（Issue 已关闭或「暂缓」的不建，在 Issue 下留言），跑 check 与 smoke，大约八分钟
  → 只含内容包（新增或修改的文件都要在 Issue 里点名，完整路径或裸名都认；Issue 开着且不暂缓）的：automerge.yml 自己合，squash 成一个提交
  → 动了别的文件、Issue 暂缓或已关闭：CI 在 PR 下留言「等维护者审」；
     haiku 汇总 CI 结果与改动文件 → 黄档（引擎、数值、界面）sonnet 先复审 → 维护者看结论，全绿无冲突就合（红档等负责人点头）
  → 红了：CI 自动给 PR 打「要改」和「给:作者」、评论失败的步骤，作者的 wait-for-work 先领回去改，推回原分支（推送后「要改」自动摘掉）。
     smoke 失败 CI 已自动重试一次；禁止推空提交「重跑 CI」。维护者想退回别的毛病，在 PR 里写意见，自己打这两个标签
  → 合并后：依赖它的下一件自动放行
```

维护者自己的活（引擎、界面）同样走 PR，由 sonnet 写、haiku 跑测试、sonnet 复审。

## 五、省 token 的规矩

- **规格一次写对**：每件 Issue 写明允许改的文件和机器验收，返工少，维护者不必逐字审。
- **结论不搬原文**：助手的回报只要结论和关键行号；维护者不重读大文件、不读完整日志。
- **测试只跑一次**：本地不跑全套给自己看；全套交 haiku，或交给 CI。
- **试玩按段量**：一段做完派一个 sonnet 试玩者按固定路线玩一遍，数三个数，不每次开四个。
- **巡检用便宜的档**：每两小时的巡检在新会话里用 Sonnet 跑（合并、记结果、退回），不叫醒维护者的长会话。
- **不轮询**：等 CI、等工具都靠通知；协作者等任务用 `wait-for-work.mjs`。

## 六、量一量流水线本身

每天的「昨天合了什么」里附三个数：每个工具合了几件、返工几次、空等几小时。空等多的，先查是不是维护者的规格、样板卡住了它。

## 七、一个工具的一天

```

```
