| B 人在 | 说到的人，一天里至少有一个时辰真在说到的地方（作息用 `engine/world.ts` 的 `roomNpcs`、`roomObjs`） |

## 机器查不到的

这些没法机器枚举，表里没有，查的人要知道：

1. **剧情卡片和战斗结局里面的小段**：心事、差事、世事只查到「触发它的那个动作」这一层。卡片里先后选哪个、战斗输赢以后接什么，不当作阶段。（机器玩家 `tests/zoubian.test.ts` 管这些走不走得通。）
2. **没写 `who` 的心事阶段**（序章第 3 步、丐帮「讨一顿饭」、藏经阁第 1、2 步、全真「踏罡步斗」，共 5 个）：找谁没记在数据里，B（人在）、D（时辰）只查标题或盘算里写明「找某某」的（全真那一步写了「找抱朴」，按名字查了）；其余只查 A、C（去哪、走得到）。
3. **点了名才写时辰**：心事阶段没点名的人（如草上飞）不写时辰，这是「没点过名的人不提」的设计，D 项只查点了名的。
4. **世事的「做不成」**：见闻簿世事行只显示 `now` 一句，插手的人死了、走了，没有地方写缘故，所以世事只查 A～D，不查 E。
5. **世界状态、伤势这类条件**：搭存档时拨不成立的条件（`w`、`wounded`），原样放着；作息里不是时辰的那部分条件（旗标、差事）按「走到这一步多半成立」算（宽松），所以「要先有旗标人才在」这类断线查不出，只查得出「怎么都不在」。
6. **打听的话**：D 项只读世事步的 `now`、`news`、`self`，不枚举打听（`engine/chuanwen.ts` 的 `ask`）能问出的 `knows`。
7. **师门升级（`sectNav`）、近处有事（`leadsNear`、`gigLead`）、零工**：不在「事」的枚举里，这一步没查。
8. **限期够不够**：只手算了有线头的差事（往返路程都在限期之内），没做成机器检查。

## 用法

- 补一条：改内容文字，跑 `npx vitest run tests/xiansuo.test.ts`，对应那一行会报「预期失败却通过了」，把 `tests/xiansuo.test.ts` 里 `KNOWN_BROKEN` 对应的那一行删掉，同时删本表对应的行。
- 新写一件事、一个阶段，没线索，这个测试就红；不要往 `KNOWN_BROKEN` 里加，补线索。
- 事、阶段改了名或删了，`KNOWN_BROKEN` 里的旧键要同步删（测试会提醒）。
