# 第一批任务（10-09 晚）

依据：`docs/gugan.md`（骨干计划、北极星）、`docs/decisions.md` 最后几条。负责人 10-09 晚：「先深思熟虑，谋定而后动；写出高质量的任务，先抓大，再抓小；积累一批任务之后，开始布置作业」「避免像现在，写了一大堆，但是都不能兑现」「战斗系统的形式我认可，但文字描述的魅力还可以加强，武功的效果还有提升空间，武学的层级带来的视觉效果差异、描述的层级不一样，这些很重要」。

## 一、开发顺序（先抓大）

**排序的道理**：一样东西要先有玩家碰得到它的路，再写它的内容；越是每次上线都碰到的，越先做好。

| 段 | 做什么 | 为什么排在这里 |
|---|---|---|
| 一 | **接通循环**（S1～S7）：夜里不被锁、来钱路、反馈说真话、线索不断、战力评语、失败缓冲、被动合璧进实战 | 每次上线都碰到；不接通，后面做什么都会被截断 |
| 二 | **战斗与武学的表现**（S8）：同一招在不同境界写法不同、看起来不同；武功的效果在战报里看得见；突破有分量 | 战斗每次都碰到，武功是负责人最看重的；先定下分层写法的样板，后面谁写武功都照它，免得写完再返工 |
| 三 | **小而完整的扬州**：新开局（药船被扣）；漕帮、府衙、盐号三股势力和二十个有诉求的人；各家的地盘（含六扇门）；在扬州能拜的两三派的门派生活；营生扩成一条路 | 地图不往外铺，往深里做；门派不求多，求在扬州过得上那种生活；开局放在这一段，因为它要用到第一、二段做好的钱、战斗和反馈 |
| 四 | **第一卷收尾**：扬州擂台（定期开）、少年英雄榜和名号、江心废墟（第一个秘境）、一条靠理解的谜链 | 剧情收口放在后面：它要教玩家的系统得先有；先写剧情就会像第二回那样只剩一句「日后再说」 |
| 五 | **复制到第二卷**：镇江、苏州按同一模板，再加门派 | 第一卷试玩达标以后才做 |

**先剧情、先地图还是先门派？** 三样都不先铺开。地图只做深扬州一处（第三段），门派只做扬州能拜的两三派（第三段），剧情先只改开局一件事（第三段），卷末收口放第四段。没有入口、机器玩家走不到的内容一律不开（已经写了的十三派武功、九十二门没入口的武功先冻着，不删）。

**每段做完怎么量**：一个 sonnet 试玩者按固定路线玩一遍（比四个角色省），数三个数（有意义的决定多久一个、无事可做几次、想关掉几次），对照 `docs/gugan.md` 的五条验收。分数变好才进下一段。

### T4 反馈说真话（S3）—— Codex
- 依据：试玩里「掂斤两」读的是此刻气血（柳寒舟先说远不如你，打完说远在你之上）；闭关七日升了两门第二重，结算一字不提；「习得」以外的成长都没有醒目提示；勒索写「收了钱」银两 +0、撬锁和「来一手」是死按钮。
- 做什么：
  1. `kanren`（`src/engine/zhaoshi.ts:124`）按满气血满内力、不带伤比实力；带伤时另起一句「你眼下带着伤」。`fight.ts:100` 的落伤封顶照旧用当前状态。
  2. 升重（`src/engine/growth.ts:44`）、升档（`src/ui/shell.ts:172-178` 的 `tierUp`）、习得（`growth.ts:72-75`）改成一张醒目的「突破」卡（浮层，写清升了什么、多了什么本事，点一下收起）；同一时刻有几件，合在一张卡上。
  3. 闭关结算（`src/ui/chuguan.ts:21-52`）把升重放在最上面，用突破的样式。
  4. 勒索、撬锁、来一手：逐条核实（grep 原文），改成文字和效果一致；补不了效果的改文字，不留死按钮。
- 不做：不改战斗形式、不改数值。
- 验收：新增测试（满状态与带伤掂出同一档实力、带伤多一句；升重和升档各出一次突破卡）；`npm run check`、`npm run build` 通过。
- 依赖：T1 合并后开工（都动 `src/ui/chuguan.ts`）。

### T5 战力和评语第一版（S5）—— 维护者先定公式，Codex 实现
- 依据：负责人「缺乏战力系统和评价系统」；试玩十三天档次不动、名号一栏是「—」。
- 设计（维护者定）：
  - **战力**：拿真引擎（`Duel`，含 T3 接进的被动合璧）把玩家满状态和一串标准对手（每档一个、档内分上中下）各打若干场，按胜率落在阶梯上，换成一个数（不入流约一百起，每档约一百五十）。同一套算法也给认得的人算，人物页列「认得的人谁强谁弱」。
  - **评语**：档次加档内位置加一句江湖口吻的话（例：「三流中段：寻常镖师打得过，碰上二流好手还得避着走」），不出现规矩和数值词。
  - **离下一档差什么**：沿用 `nextTierLine`（`src/engine/ren.ts:85`），并写「练什么最快」（哪门武功离下一重最近、手上历练够闭关几日）。
- 验收：同一存档算两遍结果一样（种子随机）；人物页和江湖页顶栏显示；试玩者说得出「我现在多强、再练什么」。
- 依赖：T3。

### T6 线索不断（S4）—— 引擎 sonnet，内容 CodeBuddy
- 依据：寻人榜要去的东关布庄找不到；小栓的舅舅只在亥子时出现、见闻簿不记；阿蕙就在府衙照壁却没人说。
- 引擎（sonnet）：手上的差事，见闻簿写「去哪、找谁、什么时辰在」（读人物作息 `at`），人不在时写什么时辰再来；做不成了写为什么。
- 内容（CodeBuddy）：逐条修布庄、小栓、阿蕙三处断线（缺地点就指到现有地点，缺人就让台词指对人）。
- 验收：机器玩家走得通三张榜；新增测试：每件差事的交差人在见闻簿里有时辰。
- 依赖：引擎部分先合，内容再开。

### T7 失败有缓冲（S6）—— sonnet
- 依据：押镖遇伏，镖丢、记过、手和内息二级重伤，出发前不提示内力只剩十二。
- 做什么：接镖、出发时提示自身状态（气血、内力、伤）和掂出来的风险；一场败仗的伤按强弱封顶（已有 `fight.ts:100`），走镖丢镖不叠加重伤；文字照实说。
- 依赖：T4（共用掂斤两）。

### T8 武学的层级表现（S8）—— 维护者定样板，sonnet 实现，minimax 照样板成批写
- 依据：负责人「文字描述的魅力还可以加强，武功的效果还有提升空间，武学的层级带来的视觉效果差异、描述的层级不一样，这些很重要」。现在一招只有一段描写（`MoveDef.text`，另有 `alts` 换着说），第一重和第七重写得一样；对手的反应是几个通用句子；被动和合璧生效时战报里看不见。
- **T8a 规格与引擎**（sonnet 照规格写）：
  - 境界分四段：**生**（第一、二重：初窥门径、略有小成）、**熟**（三、四重：融会贯通、炉火纯青）、**精**（五、六重：登堂入室、出神入化）、**化**（七重以上：登峰造极、返璞归真、天人合一）。
  - `MoveDef`、`PerformDef` 加可选的 `lv: { 熟?: string[]; 精?: string[]; 化?: string[] }`；出招时按这门武功当前的境界段取，没写的段往下一段退，最后退到 `text`/`alts`。
  - 对手挨招、闪避、招架的反应按双方差距分三种口气（吃力、相当、碾压），各一组句子。
  - 战报的样子随段不同：熟段招名加粗；精段招名换强调色、句前多半句「意」；化段整条另起一格、字距放宽，像一笔题字。绝招、杀招另有样式。浅色深色两种主题都要好看（`src/styles/app.css`）。
  - 被动、合璧生效时在战报里说一句（护体卸力、身法闪过、回气、合璧发动），每场同一句最多一次（`pickFresh`）。
- **T8b 样板**（维护者写，金庸编辑角色审）：寒江剑法、寒江心法、踏雪无痕三门（主角家学，每个玩家都会用到），每招四段写法，加一页「层级写法」说明进 `docs/wenfeng.md`：生要形似而滞，熟要快准利落，精要意到招随、能借势，化要返璞、不着痕迹；同一招四段要看得出是同一招。
- **T8c 成批**（minimax，照样板）：第一卷玩家学得到的武功（太祖长拳、武当长拳、太和心法、惊鸿剑、断水，和扬州能拜的门派的入门武功），每门每招补熟、精、化三段；金庸编辑角色抽审，返工退回 minimax。
- 验收：同一招在第一重和第五重打出来，战报文字和样子都不同；`tests/` 加检查：写了 `lv` 的武功四段都能取到、没有现代词；手机截图浅深两色各一张。
- 依赖：T8a 先合，T8b 再写，T8c 最后。T8a 可以和 T4～T7 并行（动的文件不同：`fight.ts` 的出招描写和 `app.css`）。
