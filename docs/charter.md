# 项目宪章

《江湖夜雨》的根本原则。**只有项目负责人能修改本文件。**

所有设计、开发、内容、审查都要符合这里的每一条。维护者（Claude）、协作者（Trae 等）、每日审查、试玩员遇到冲突时，一律以本文件为准；拿不准就在 Issue 里问负责人，不要自行变通。

每一条都写明了「怎样守住」：
- **测试**：由机器自动检查，违反了 CI 就会变红。
- **审查**：由每日审查逐条核对。
- **试玩**：由试玩员在试玩报告里打分。

标「待建」的，是检查机制还没有做出来，已排进 `docs/roadmap.md`。

| 编号 | 原则 | 怎样守住 |
|---|---|---|
| **P1 平台与操作** | 手机竖屏，高清。全程点按，不让玩家输入指令。唯一的例外是解谜时输入答案。 | 审查；试玩 |
| **P2 视觉** | D「素白卡片」风格：清爽醒目，层级清晰，是新世代的文字 MUD。浅色、深色两种主题都要好看。 | 审查（截图）；试玩 |
| **P3 文笔** | 文笔看齐金庸；武学的分类和机制参照北大侠客行，鼓励创新。对白用「」，数字写中文，不用现代词。 | 测试（文风检查）；审查 |
| **P4 武学宇宙** | 以金庸群侠为底，可以直接用金庸的武功、门派、典故；书中人物不作为 NPC 出场。武功有品级之分，但勤学苦练，任何武功都能技惊四座：境界的分量大于品级。武功之间要有不同的增益和减益、震撼的杀招、讲究的搭配。 | 测试（武功校验、平衡测试、出场人物名单）；审查 |
| **P5 战斗** | 即时回合，保留文字的魅力，又有即时的快感和可视化。见招拆招走「以己之长」：应对来自自己练成的武功，成算由修为和对手这一招的强弱算出。**拒绝靠找规律就能破解的机制。** | 测试（成算公式）；审查；试玩 |
| **P6 自由** | 武侠里的 GTA：世界大，身份多（参军、报效朝廷、走镖、拜入门派、自立门派），主线可以不做。江湖里有恩怨情仇、神兵利器、绝世武功、美女兄弟。 | 审查；试玩 |
| **P7 拒绝快餐** | 乐趣来自养成和漫长的期待。认真玩大约**三个月现实时间**才能练成宗师。挂机、闭关按现实时间累积，有上限，**不能速成**。境界有瓶颈，要靠机缘才能突破。 | 测试（养成节奏，待建）；试玩 |
| **P8 探险与解谜** | 神兵利器、绝世武功绝不唾手可得，要靠机缘巧合、洞察和奇思妙想。线索藏在对话、传闻、碑文、诗句里；秘密不用任务标记带路。 | 审查；试玩 |
| **P9 任务质量** | 拒绝低质量任务，不做跑腿、杀几只怪、送个东西这类。每个任务都要有人物动机、两难的选择、选择的代价，结局要有余味。要让玩家体会爱恨情仇，沉浸感优先。 | 审查（任务质量清单）；试玩 |
| **P10 挂机** | 重复性的操作，比如练功，交给挂机和放置；挂机同样受 P7 约束。 | 审查；试玩 |
| **P11 故事** | 主线是原创的，发生在大胤景和年间，玩家可以不做主线。真相（`docs/story.md` 第二节）不能提前剧透。 | 测试（剧透词）；审查 |
| **P12 多人** | 可以和几个朋友一起玩：先做异步江湖（账号、云存档、江湖榜、传闻、书信、切磋分身），再加实时（同地相见、聊天）。单机也必须完整可玩。 | 审查；试玩 |
| **P13 零成本** | 托管、后台、自动化一律用免费额度，不产生费用。 | 审查 |
| **P14 协作与质量** | 维护者做设计和系统，协作者批量产出，机器把关，每日审查。协作者质量差时，必须明确告知负责人。尽量节省 token。 | 测试（CI）；审查（每日评级） |

## 修改宪章

1. 只有负责人能提出或批准修改。
2. 修改时，在 `docs/decisions.md` 里补一条决策记录，写明改了什么、为什么改。
3. 维护者发现某条原则和实际开发冲突时，先在 Issue 里提出来，等负责人拍板，不要先改代码再补说明。
