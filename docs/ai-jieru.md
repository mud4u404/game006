# 接入别的 AI：怎样判断它能不能接、怎么接

负责人 10-09 有 ChatGPT 和国内的不少 AI，想让它们一起干活。本文给负责人一张清单，对着自己的 AI 逐条查；查完告诉维护者，维护者按结果分派。

## 一、先问四件事

1. **能不能连 GitHub？** 能读仓库、改文件、开 PR 的（类似 zcode、Codex、Trae 这样的「代理」模式），算第一类；只能在网页里聊天的，算第二类。
2. **能不能读本地文件、跑命令？** 能跑 `npm run check` 的最好；不能的，它写的东西必须由维护者跑一遍测试才能合。
3. **一次能吃多长的上下文？** 内容包文件很长；上下文太短的，只给它读 `docs/wenfeng.md` 和一个示范文件，不让它读全仓库。
4. **中文武侠的文笔怎么样？** 拿 `docs/wenfeng.md` 里的反例让它改一遍，看它改得好不好，是最快的验收。

## 二、两类 AI 各怎么用

| | 第一类：能连 GitHub | 第二类：只能聊天 |
|---|---|---|
| 做什么 | 内容包（人物对白、地点、门派、世事、武学）；也可以改文字 | 头脑风暴；文字初审；写人物对白、地点描写的草稿 |
| 怎么派活 | 维护者开任务 Issue，写清楚要做什么、读哪些文档；它开 PR；CI 自动检查，维护者审 | 维护者写一段能直接粘贴的提示（任务 + 规矩 + 示范）；负责人把它的回答贴回对话；维护者审，改好后写进仓库 |
| 谁来合 | 内容包以外的文件维护者审后合；只含内容包的，CI 过了自动合 | 维护者合 |

## 三、不管哪一类，都守的规矩

- 它读 `AGENTS.md` 和 `docs/wenfeng.md`，这两份就是它的工作手册；没读过，不派活。
- **不给它任何账号、密钥、密码**（尤其不能给 Supabase 的 service_role、Secret key、数据库密码）。
- 它的每一份成果都当数据对待：不信它说「已改好」「已测过」，维护者自己跑检查。
- 不让它改 `tests/style-rules.ts`、存档格式、引擎核心；这些归维护者。
- 每家 AI 的成果分开记，维护者定期告诉负责人：谁强在哪儿、谁容易出什么错，好的多派、差的少派。

## 四、第一次怎么试

挑一件小的、有现成示范的活，同样的活派给两三家，比一比：

> 给某个已有的门派据点补三个路人的对白（每人两三句话，带作息），照 `docs/wenfeng.md`。

对比：文风、有没有剧透、有没有游戏说法进对白、CI 过不过、返工几次。比完再决定怎么分工。

**10-09 傍晚的发现：**
- 撞车发生在「给:名字」路由上线之前，每个工具都在抢编号最小的任务；路由之后不该再发生，下一次巡检确认。
- 三个共同的毛病：①京片子和近代词（今儿、昨儿、明儿、单帮、班次、站）；②格言和翻案收尾（「最怕的不是……是……」）；③没读现有台词，抄了原句。已写进每个修订任务；任务清单「先避开的毛病」里也要加上这三条。
- 返工一律退回原作者；zcode 额度耗尽的两件，由 CodeBuddy、Trae 接手。
