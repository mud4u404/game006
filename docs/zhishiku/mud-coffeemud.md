# CoffeeMUD：派系与 NPC 经济

来源：https://github.com/bozimmerman/CoffeeMud （Apache-2.0）

读的是文本，没有 clone、没有运行。本篇只记机制和布局，不抄代码。

出处写法：`com/planet_ink/coffee_mud/…` 是仓库里的路径。

## 一、它怎么做的

### 1. 派系（Faction）：一个人对每个势力各有一个 −100～100 的数

核心在 `Common/DefaultFaction.java`。一个派系不是一个「好感度」，而是**一整套规则**：

- **档位（Range）**：`RANGE=low;high;名字;代码名;立场`，形如 `0;100;Sample Range;SAMPLE;`。人物的派系值落进哪一档，就触发那一档挂着的效果。默认 `0;100`、中位 50，档位可以自己切。
- **涨跌事件（ChangeEvent）**：`CHANGE=事件;方向;系数;标记;目标`。
  - 事件是**别的系统抛出来的**——一个能力类别、一条消息类型（「偷东西」「打了对方」）、一次社交动作。
  - 方向有九种：升、降、相反、抹掉、抬到下限、抬到上限、加、定向、远离。
  - 系数是百分比，可以带 `OUTSIDER`（只对帮派外人生效）、`SELFOK`、`JUST100`。
  - 触发参数还能写 `WITHIN=n`（这事件 n 个 tick 内发生过才算）、`CHANCE=n`、`WAIT=n`。
- **势力之间互相牵连（Relation）**：`RELATION=另一派系;系数`。**甲涨多少，乙按系数反向动。** 「帮了甲就得罪乙」不是一个一个事件手写出来的，是一张系数表。
- **涨跌快慢（ZapFactor）**：`FACTOR=涨的系数;跌的系数;mask`。同一个人物，对某些对象涨得快、跌得快。
- **整派速率**：`RATEMODIFIER`。
- **到档触发**：`AFFBEHAV=行为名;参数;mask`——进了这一档就给这个人挂上某个 Behavior；`ABILITY=标记;下限;上限`——在某个数值区间里才使得出某门能力。
- **到档说什么**：`REACTION=档位码;在场者mask;反应对象;参数`——到了某档，面前站着符合 mask 的人，就对他说一句。
- **初值与自动选项**：`DEFAULT=数值;mask`（符合条件见面就给这个初值）、`AUTOCHOICES`（到达某档时可选的身份）。
- **零开销档**：某一档没挂 Listener、Behavior、Reaction，`noListeners`／`noTickers` 直接跳过。

**入场打招呼**：`USE LIGHT REACTIONS` 打开后，玩家进入房间时，房里每个 NPC 按自己对玩家的派系值播一句反应——这是「你一进屋，满屋人先看你」的机制。

### 2. NPC 行为：拼装，不是继承

`Behaviors/` 下 **99 个**行为，名字就是它们的分工：巡逻（`ActiveTicker`）、好斗（`Aggressive`）、乞讨（`Beggar`）、贿赂守门人（`BribeGateGuard`）、门卫（`DoorwayGuardian`）、捉拿逃犯（`Arrest`）、尸体处理（`CorpseEater`／`CorpseLooter`）、聚众（`Conquerable`）、天气反应（`Drowness`／`Druidness`）、传教（`Clericness`）……

每个 Behavior 是一段可挂到人身上的独立逻辑，能挂多条，靠 `AFFBEHAV` 的 mask 决定在什么派系值下生效。**一个 NPC 是若干 Behavior 的组合，不是一个类。**

### 3. 商店

`Common/DefaultCoffeeShop.java`：

- 库存是一串 `ShelfProduct`＝物品 ＋ 数量 ＋ **价格码** ＋ 货币。
- 货来自可插拔的 `ShopProvider`（`getStock`），**货怎么补进来是可换的**，不是写死在店里。
- 价格是一个「价格码」，**核心里不按派系好感算价**。

## 二、我们能借什么

对照我们自己的：`src/engine/shenfen.ts`（身份与差事）、`S.xia`／`S.eming`（`src/core/state.ts`）、`docs/decisions.md`「恶名能洗、命债不能」、#321（恶名高了店家换口气）、#284（物价总表 `docs/jiage.md`）。

**1. 涨跌写成「事件」而不是写在具体动作里（借鉴 ChangeEvent）。**
他们的好感是**被别的系统抛出来的事件**涨的：打了人、帮了忙、偷了东西。我们现在是侠义／恶名散落在各个效果里（`engine/xingdong.ts` 写的）。把「什么事涨多少」收成一张表，好处是**加一条新事件不用去改十处动作**，也便于核对「哪几件事真的在动我们的数」。

**2. 势力之间用系数表互牵（借鉴 Relation），一条就够。**
我们要的「帮了汪家就得罪漕帮」不必在每个任务里手写两边——一张 `甲↔乙` 的系数表就能表达。这一条和我们的北极星「势力相撞自然生事」直接相关，且比逐任务手写更不容易漏。

**3. 「帮了甲得罪乙」的代价要有上限（借鉴 ZapFactor 的涨／跌分开）。**
他们的 FACTOR 能让同一个人物**对某些对象涨得快、对某些对象跌得快**。我们现在的侠义／恶名是一个数涨跌两向分开，但**不分对象**。可以借的是：一次帮助对「本来就恨你的人」伤害更大，对「本就敬你���人」几乎不动——这样才不会出现「帮谁都得罪人」的死法。

**4. 零开销档（借鉴 noListeners／noTickers）。**
我们的 `S.xia`／`S.eming` 是一直挂在存档里的。CoffeeMUD 的做法是：某一档没挂任何效果，就完全不计算。这一条对我们的启示不是性能，是**「档位」这个概念本身**——我们目前只有连续的数值，档位（生疏／相熟／知交／结拜／师徒）散落在 `rel` 的字符串里（见 `src/ui/views/jianghu.ts:110` 那一串判断）。把它变成有名字、有边界的档，涨落的叙述（「升了一档」）才有依据。

**5. NPC 是行为拼装（借鉴 Behaviors）。**
对我们正在做的「二十个关键人物，诉求相撞自然生事」：每个人物应该是若干条独立的行为（他想要什么、他盯着谁、他几点在哪儿、他怎么反应），而不是每人一段专属逻辑。这对 #327 那类「关键人物活气」的活尤其对路。

**6. 价格码与货来源可插拔（借鉴 ShelfProduct + ShopProvider）。**
#284 的物价总表把价钱写死在内容里；他们把「卖什么」和「从哪来」拆开。这对我们后续要做的动态物价（战时涨、灾时涨）有参考：把**价**和**供货**拆成两个可换的来源，不必改内容。

## 三、不借什么、为什么

- **不借「一个派系一整套规则」的重。** 他们的 DefaultFaction 有二十来种配置键（DEFAULT、AUTOCHOICES、FACTOR、AFFBEHAV、REACTION、ABILITY…），是一个通用 MUD 为兼容几十种玩法留的扩展点。我们要做的是「三股势力、二十个关键人物」的扬州（`docs/gugan.md` 第二阶段），内容量小得多，照搬那套配置面只会让内容难写难查。**只借其中「事件触发」和「势力互牵」两条。**
- **不借百分比系数当主要机制。** 他们的涨跌几乎都是 `factor` 百分比。我们是整数、而且多数后果是离散的（一条见闻簿、一段关系、一个旗标）。借百分比会把「他说了一句什么」变成「好感 +5%」。
- **不借「好感自动改价」。** 没核实到出处（见上面「未查到」），而且 #284 刚把全游戏价钱对完一遍、还标了六条可疑——在价钱总表站稳之前，让价钱随好感浮动会立刻制造一批「说不清」的数。
- **不借 Behavior 的触发器（`ActiveTicker` 那类世界定时器）。** #337 那份 Evennia 笔记已经记了我们的判断：事件挂时辰、不挂现实分钟（`docs/zhishiku/evennia.md`）。这条对 Behavior 同样适用。
