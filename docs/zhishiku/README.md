# 知识库：文字 MUD、武侠游戏、沙盒游戏

负责人 10-10：「帮我建立一个文字 MUD 的知识库，然后 GitHub 上下载各种源码，没事干的时候，你可以安排人手调研，从中找到灵感或者对我们有帮助的东西，也可以为将来的开发提供方向……你也可以去研究下一些沙盒游戏，武侠游戏，会有帮助的。」

## 规矩

- **只记机制和布局，不抄文字和代码**（版权）。引用写出处：仓库地址、文件路径或公开资料的链接。
- 源码不进仓库：调研时 `git clone --depth 1` 到临时目录，读文本，**不运行**里面的任何程序；GBK 的用 iconv 转码。
- 每份笔记三段：**它怎么做的** → **我们能借什么**（对照 `CLAUDE.md` 第二节的原则和北极星） → **不借什么、为什么**。末尾列「建议进设计的三到五条」，每条带出处。
- 笔记放本目录，一个来源一份，文件名用拼音或英文。写完在下面的「索引」里加一行。
- 好点子同时记进 `docs/linggan.md`（灵感本）。
- **谁来做**（负责人 10-10：「调研的事情只能是你或 codex 做，其他人不碰」）：只由维护者（派自己的 sonnet 助手）或 Codex 做；拆开源 MUD 源码、消化资料这一类可交 zcode（负责人 10-10 补：「你可以让它去拆源码，帮你消化资料」），笔记由维护者审。其余协作者不领。调研 Issue 一律带「调研」和「给:claude」（交 Codex 的改成「给:codex」），接活脚本不会派给别人。
- **节拍**：每日巡视至少推进一件；挑和眼下要做的设计最相关的那件先做（例：要做世事重来，先读环世界）。
- **第一批**（10-10）：#335 炎黄、#336 侠客行 100、#337 Evennia、#338 CoffeeMUD、#339 太吾绘卷、#340 环世界、#341 骑砍、#342 矮人要塞、#343 金庸名场面倒推、#344 Sunless Sea 与侠客风云传。

## 怎么用（复用）

负责人 10-10：「建立一个可以复用的知识库，为项目开发助力。」知识库不是读书笔记的堆放处，是**动手做一个系统之前先查的地方**：

1. **开工先查**：写设计稿、开任务之前，按下面「按问题查」找到相关笔记，读它的「建议」一节，在设计稿里写一句「参考了哪份笔记的哪几条，采纳了哪些、没采纳哪些」。
2. **建议有去向**：每份笔记末尾的建议，逐条标状态：「新」「采纳 → #N 或设计文档」「不采纳：原因」。维护者每日巡视时把采纳的写成任务。
3. **一份笔记一个来源**，按问题挂到下面的表里；同一个问题可以挂多份，对照着读。
4. **过时就改**：我们的系统变了，笔记里「我们能借什么」那段跟着改一句，别让它说错我们自己。
