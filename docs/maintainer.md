## 项目是什么

《江湖夜雨》：单机、手机竖屏、全程点按操作的中文文字武侠游戏。目标是「武侠 MUD 里的 GTA」：世界大，做什么都行。

- 试玩网址：https://mud4u404.github.io/game006/ 。main 一更新，就自动部署到这里。
- 设计文档：`docs/design.md`。第八节「规模化路线」是接下来的主线工作。
- 剧情文档：`docs/story.md`。第二节是只给设计者看的真相。
- 内容格式：`docs/content-guide.md`。
- 协作规则：`AGENTS.md`；审查和合并规则：`docs/auto-review.md`。

## 项目负责人的偏好（已经定下的事，不要再问）

- **界面**：D「素白卡片」风格。清爽，层级清楚。不让玩家输入指令，全部点按。
- **战斗**：即时回合制，加上见招拆招。应对方式按「以己之长」：从自己学会的武功里选，每种应对都有成算。成算由修为对比对手这一招的强弱算出来。**不要做靠找规律就能破解的机制。**
- **重复操作**：练功这类重复的事交给挂机和放置；主线可以不做。
- **规模**：在意体量，要的是 GTA 式的自由度。
- **成本**：在意 token 用量。能交给机器检查的交给机器，能交给协作者写的交给协作者。
- **沟通**：
  - 用中文，不堆术语。
  - 操作类的说明要一步步写，写明点哪个按钮。
  - 有需要负责人拍板的事，用选项问，并标出推荐项。

## 分工与流程

| 谁 | 做什么 |
|---|---|
| 维护者（Claude 主会话） | 设计、系统架构、数据格式、测试用例、CI。写「功能」Issue 时附上设计卡和测试用例 |
| 协作者（Trae 等，可以换） | 写内容；按测试用例实现功能。负责人给它发一句开工指令（`AGENTS.md` 第八节）它就开工 |
| GitHub Actions | 检查每个 PR。只新增内容包的 PR，全部通过就自动合并，并自动部署 |
| 每日例行任务（Claude，用 Sonnet） | 北京时间每晚运行一次，照 `docs/auto-review.md` 执行：精修当天合并的内容、审功能 PR、补发任务 |
| 项目负责人 | 决定方向，给协作者发开工指令，合并功能 PR |

- 维护者自己的分支用 `claude/` 开头，改动都走 PR，由负责人合并。
- 每日例行任务在 claude.ai/code/routines 里叫「江湖夜雨 · 每日一审」。每次运行的记录都写在 Issue #16「【记录】每日一审」下。

## 代码地图

```
src/core/     状态 S、存档（键 jhyy-save-v2）、时间、工具函数
src/content/  types.ts 数据格式；index.ts 合并内容包（自动补回程出口，按 at 放置人物）
              skills.ts 武功与境界；packs/*.ts 内容包，按文件自动收录
src/engine/   dsl.ts 条件与效果；world.ts 寻路、动作；formulas.ts「以己之长」成算；growth.ts 熟练度与突破
src/ui/       shell.ts 外壳与 hooks；explore/fight/story.ts；views/ 下是五个标签页
tests/        content.test.ts 内容校验；style-rules.ts 文风与剧透规则；engine.test.ts
scripts/smoke.mjs  冒烟测试（npm run smoke）
```

几个关键约定：
- **效果分两类**：
  - 一般效果在 `engine/dsl.ts` 的 `run()` 里执行。
  - 开打、开剧情这两种要界面接手。`run()` 只把它们记进 `Outcome`，由 `ui/shell.ts` 的 `afterOutcome` 处理，这样避免循环引用。
- **成算的算法**：
  - 火候 = 境界 × 10 + 对应的属性。
  - 成算 = 基数 + (火候 − 对手这一招的强度) × 0.025，结果限制在 5% 到 95% 之间。
  - 基数一般是 0.5，抢攻是 0.35。
- **改动之后**：
  - 改了数据格式，同时更新 `docs/content-guide.md` 和 `tests/content.test.ts`。
  - 加了能让机器检查的规则，写进 `tests/style-rules.ts`。
