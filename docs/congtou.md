# 从头开始（负责人 10-11 定）

负责人 10-11：「我打算继续在原来的仓库里进行调整，由你跟 codex 携手，让我们从头开始。」

## 为什么
前几天在地基没想清楚时就急着上量：门派、城市、产业、几百件任务。结果悬而未决的多、真正闭环的少、质量没把握。负责人的诊断：应当从小开始，从一个小镇、三五个人、最基础的东西开始；战斗可以打磨很久（普通人、会点武功的、武学大师），武功升级前后各是什么效果，都要先搞清楚。

## 根
- `docs/dangan-1011.md`：负责人与个人助理整理的共识档案，原文照存。设计一律以它为根；它的「已否定」不得换个名字塞回来。
- 旧仓库里的代码、内容、文档是**零件库**，不是定案：能用的经验证后捡回来，不能用的不迁就。

## 怎么做
1. **只有维护者（Claude）和 Codex 两家**。其他协作者（minimax、Trae、Qoder、CodeBuddy、zcode 等）暂停领活，`scripts/wait-for-work.mjs` 只给 codex、claude 派活，而且只派带「从头」标签的 Issue；旧任务一律不派。暂停的工具运行它会一直等着（不花额度），不会空转。
2. **先讨论，后原型，再代码**。一个问题一个问题地关（顺序见下），每关一个，写进本页的决策记录；能试手感的，先做小原型给负责人在手机上试。
3. **不开值班、不刷任务库**。每小时巡检、每日巡视、每日一审都已停用；「任务库常保 50 件」「每家至少两件」的规矩暂停。
4. 旧的开着的 Issue、PR 先不动，也不再派新的；以后按新标准逐件挑回或关掉。

## 先关的问题（顺序可和负责人再议）
1. 普通人怎么打、会武之人怎么打、高手怎么打（档案 Q10、Q09）
2. 基本功、具体武学、身体条件、内力怎么分工（Q07）
3. 武功练前练后，差别怎么让玩家亲手感到（Q04、C05）
4. 小镇讲什么故事、为什么与玩家有关（Q15、Q16）
5. 界面骨架（负责人 10-10 给的七张效果图，档案第四章）
